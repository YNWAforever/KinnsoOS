# Creator draft navigation

The creator guide editor previously lost unsaved edits when client navigation unmounted it before its 900ms autosave started or received acknowledgement. It now uses the existing draft navigation provider for controlled same-origin links, programmatic navigation and same-document browser traversal. The dialog offers Save and leave, Discard unsaved edits and Continue editing in English and Traditional Chinese. Reloads, tab close and cross-document traversal use the native beforeunload warning.

Save and leave uses the existing creator save command and succeeds only after acknowledgement of the current edit revision. A rejected save, conflict, older edit revision or unmounted editor cannot authorize leaving. An uncertain save retains its original request ID. Pending publish/withdraw commands must be reconciled through the existing explicit retry control; leaving cannot replay those public actions. Canceling navigation while acknowledgement is held keeps the editor open even if the save later completes. Discard retains the last confirmed draft. Existing device-draft copy remains the default.

## PR #103 hardening follow-up

The shared guard now installs a conditional native warning in layout and reads its current dirty/busy state at unload, covering editors before any editor-specific passive listener. Clean pages keep back-forward cache eligibility. Same-document Back/Forward does not fire `beforeunload`. The original Navigation API handler also left browsers without that API unprotected, and canceling Forward in Chromium could suppress repeated `history.forward()` attempts. The provider now tracks its own history positions, restores the editor entry before Next handles `popstate`, then replays the requested traversal only after save/discard. It preserves opaque router/user history state, including native hash entries, and makes retired wrappers transparent during StrictMode cleanup. In-page hash traversal keeps the editor open without a leave prompt. Early child effects that call `replaceState(null)` also retain the opaque current router state before Next installs its passive history wrapper; a regression models that insertion/layout/passive ordering without repairing metadata in the stand-in.

A first save on `/new` must not canonicalize to `/id/edit` while any leave dialog is pending: that can remount the editor and cancel the navigation intent. Every save acknowledgement, including autosave already in flight, checks the guard’s live per-editor navigation predicate. Continue editing, Escape and Close clear the navigation intent before invoking the active editor’s resume callback. If autosave finished while the dialog was open, the callback restores the acknowledged edit URL; newer unsaved input or an unresolved command keeps the editor on its current URL until its own acknowledgement. Canonicalization and history stamping retain existing router state, including `__NA` and the router tree, when caller data is null.

Unstamped, foreign-session and pre-hydration entries cannot supply a trustworthy traversal offset. While dirty or busy, the guard stops their pop before Next handles it and recreates the source entry, then uses guarded router navigation for the requested destination. This fallback can trim the unknown Forward history chain; stamped Back/Forward retains its normal restore/replay behavior.
