## Evidence and severity limits

**AUD-01:** All four bookmark list/toggle call sites previously omitted `X-Kinnso-Intent-Actor`; trip commands already support it. Cookie authentication alone checks the account active when the request arrives. It does not ensure this is the account whose guide/Saved view originated the action. The repository now requires a UUID actor argument and returns AUTH_REQUIRED without fetching when it is missing/invalid. Actual `apiContext` tests prove account-A intent with account-B cookies fails before either actor RPC or bookmark data access. This addresses mistaken-account actions; no cross-owner RLS bypass is claimed.

**AUD-02:** Both security-definer limiter RPCs accept caller-selected IP, maximum and window and grant EXECUTE to anon/authenticated. A negative window makes the upsert reset an existing bucket; callers can also increment another IP bucket. Later migrations contain no replacement or revocation. `/api/agent` relies on this ledger before paid generation. Revoke browser mutation and move the call behind a trusted server boundary; validating the window alone leaves victim-bucket poisoning. Live abuse and billing impact were not tested.

**AUD-03:** Owner-editable `creator_social_handles` records have no verified ownership binding. `verify.ts` uses that claim and `resolveConfidence` returns `verified_signal` when the public author matches it. The isolated function check reproduced that signal for an attacker-claimed victim handle. On an administrator-opted-in `verified_signal_only` mission, SQL auto-approves and paid/hybrid approval creates a pending settlement. Actual payout still requires operations action. Later policy-setting restrictions were checked and do not establish social-account ownership. Product must define acceptable ownership proof; a safe interim manual-review policy is an engineering mitigation.

**AUD-04:** Initial scan limits count jobs; retries reset/reuse one failed job without consuming a launch ledger. The actual retry handler with an in-memory DB and simulated upstream failures accepted 25 sequential retries, launched 25 pipelines and retained one database job. Existing same-row compare-and-swap does not address this sequential path. Fix initial and retry launches together with an atomic budget.

**AUD-05:** Credential presence enables scan/sync mutation suites after automatic `.env.test` loading. Scan creates/deletes auth users and sync upserts/deletes content. MySQL reader tests activate on `LEGACY_DB_HOST`. Root `pnpm test` collects these suites without the attestation used by newer Journeys test infrastructure. No such tests or clients were executed for this audit. The problem is unsafe test orchestration, not evidence that production data was changed.

**AUD-06:** `/webhook/foso` calls `c.req.text()` before HMAC without a route body cap. The `/redirects` cap does not cover it. An externally reachable worker without a proxy ceiling is vulnerable to unauthenticated memory pressure. Deployment exposure and upstream limits remain unknown; source remediation is small and does not require changing product behavior.

**AUD-07:** A fresh anonymous read of `/en/legal/privacy` returned HTTP 200 and explicitly stated that the full notice and dedicated request contact are unpublished. The repository already contains draft policy work. Contact ownership, retention, processors and approved bilingual wording need product/privacy decisions; inventing these would be inappropriate.

**AUD-08:** Verification checks owner concurrency/daily allowance, awaits insertion, then records the launch. Concurrent distinct submissions can observe the same allowance. The unique index only serializes jobs for the same submission. This is a source-demonstrated interleaving, not a measured live incident. Coordinate with AUD-04 to avoid separate inconsistent quota implementations.

**AUD-09/10:** Root ESLint explicitly ignores Journeys and Journeys has no lint script, so successful root lint does not cover the default app. Fourteen individual `@radix-ui/react-*` declarations have no source/config/test references in web; the UI imports consolidated `radix-ui`. Parity uses the sync-owned MySQL reader and does not import its own declared `mysql2`. These are confirmed redundant direct declarations, not proof of dead transitive packages or a bundle-size saving. No additional dead runtime module was proved unreachable; demo, legacy and source-distribution paths were not deleted just because ordinary navigation does not exercise them.

**AUD-11/12:** Isolated regressions observed RPC exceptions returning INVALID/400, two immediate removal clicks dispatching two requests, and an old removal callback dispatching after account invalidation. Parse errors now remain 400, transport exceptions become retryable 503, removal locks synchronously and account invalidation clears its pending UI. Success and failure acknowledgements arriving afterward cannot repopulate it. Optional analytics guarding is additional hardening: the existing production `successEvent` already catches its own errors and was not classified as a separate confirmed defect.

## Implementation and acceptance

The change keeps product scope, locales, capability flags, schema and RLS unchanged. It completes account binding in the bookmark repository and its existing Guide/Saved callers, adds synchronous duplicate/removal guards and invalidation cleanup, and corrects unknown-outcome status classification. Existing bookmark request IDs survive retries within the flow. Unknown outcomes remain recoverable without describing them as rejected input. The corresponding-source manifest includes the new regression file.

Eleven focused tests execute actual repository/context/route/component code with only auth, database, network and framework boundaries replaced. They cover headers/cursors/payloads, missing actor, stale-account read/write denial, malformed input, unknown transport outcome, optional measurement resilience, rapid clicks, retry identity, invalidated callbacks, guide callers and late success/failure responses.

No database migration is required. Rollback is a normal revert of the PR; it requires no data rewrite. The internal bookmark repository API now requires actor identity; all four source callers were updated and TypeScript checks them. The HTTP API remains compatible with existing callers; supplied intent headers are verified by the pre-existing shared context. This header is a consistency guard, never a substitute for authenticating the user or authorizing rows.
