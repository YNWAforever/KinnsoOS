## 下一批依賴及驗收

1. **確認唯一 staging / production binding**：核對 Vercel project、origin、功能 flags、Supabase catalog，不讀出或分享 keys；成功條件是 redacted readiness report 與 target / owner 對得上。
2. **比對而非重放 schema**：沿用 migration hash packet，列 installed / missing / definition drift / grants / policies；先在可恢復 staging 演練最小 delta、rollback、重入；保留每一步證據。
3. **整合現有 PR**：本輪已整合 main `58d72e9`（#74）；#76 merge `992fc09` 的 base 是 `codex/workspace-recovery-source-contract-20261011`，並非 main。先檢查 #76 完整 ancestry 再提出後續 PR。每次整合重新核對 source ZIP、unit、DB、native、SMTP 及 performance report，不以 collector job success 代替閾值結果。
4. **具名角色 UAT**：旅人、creator、merchant owner/staff、finance、ops 跑正常、跨租戶拒絕、失權、斷線、重試、衝突。bulk 操作需有選取範圍／預覽／部分失敗回復證據；不能只測 happy path。
5. **真實內容及 pilot**：3 篇獲授權攻略→匿名閱讀→明確套用→私人修改→創作者新版不覆蓋旅人筆記；merchant brief→申請／邀請→提交→審核→有來源的收益紀錄。
6. **衡量產品价值**：建議以「首次可用行程完成率、creator 首篇可套用攻略完成率、merchant 首次合資格合作完成率」作 pilot 指標；分母、觀察期間與目標由 pilot owner 先定。此輪没有市場領先或最佳產品的比較證據。
