# Email delivery E3 — ops self-test, health, alerting and retention

**Status:** deployed and verified in production, inert. Release 8d8c023, ledger **266** (`20261110150000`), deployment dpl_CBirQWg9LRs8qBENxAAQ37kJ66sD.

## What shipped

- `POST /api/ops/email/test`: one message to the signed-in operator's own address through the same provider seam; reports delivery classification only, never the address, and honestly reports `provider-not-configured` while no provider exists.
- Ops health gains an `email-outbox` check: disabled reads healthy; enabled with failed rows or a pending row older than an hour reads degraded.
- The public aggregate snapshot gains the outbox flag, pending/failed counts and oldest pending age — counts only, no identities.
- `email-delivery-failing` alert state (hourly window) and a labelled drill, plus 30-day retention for sent/failed rows inside the sender cron.

- 5/5 template unit tests (including the labelled self-test message).
- Local 7/7: health disabled/ok, self-test delivered via console, enabled+stalled degraded, snapshot identity-free, drill reached the webhook with the right state, sender drained the queue and purged only 30-day-old sent rows, cleanup returned healthy.
