# Email delivery E2b — Resend adapter and activation runbook

**Status:** code complete, locally verified, deployed inert. Release f1a36be, deployment dpl_Hktc7LqVWhZJJ77c5An7dtUsrCgi, ledger unchanged at 268.

## What shipped

- Resend adapter: `POST https://api.resend.com/emails` with from/to/subject/text, a 10s timeout and an `Idempotency-Key` derived from the outbox row id so retried sends cannot duplicate.
- Failure handling: errors become `resend <status>: <detail>`; the API key is never included in errors or logs.
- 4 adapter unit tests: configuration requirements, exact request shape, failure redaction, local base-URL override.
- Owner decision record for E1–E3/E5 and the step-by-step activation runbook (DNS, Vercel env, verify, enable, rollback).

## What is still required for live email (owner actions)

1. Resend account + verified `mail.kinnso.com` (SPF/DKIM/DMARC).
2. Resend API key set as `KINNSO_EMAIL_API_KEY` in Vercel (with `KINNSO_EMAIL_PROVIDER=resend` and `KINNSO_EMAIL_FROM`).
3. `KINNSO_SUPABASE_SERVICE_ROLE_KEY` in Vercel so the sender can resolve addresses.
4. Redeploy, run the ops self-test to your own mailbox, then enable the flag.

## Limits

No live email has been sent. Bounce webhooks are future work, email mute reuses the in-app mute, and reminders are still read-time only.
