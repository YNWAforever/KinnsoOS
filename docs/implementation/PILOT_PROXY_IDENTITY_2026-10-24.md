# Pilot proxy visitor rate-limit identity

PR83's web pilot proxy previously sent all visitors through one receiver egress-IP bucket. The source fix reads the existing trusted `getClientIp` helper at web ingress and binds that IP, the POST receiver origin/path, exact parsed public event serialization and Unix-second timestamp with HMAC-SHA256. The receiver accepts only a canonical signature with at most 60 seconds of clock skew, before creating a client or entering its measurement sink. Different visitors have different quota keys; direct and proxied requests for the same IP keep the same existing `600 requests / 600 seconds` quota. The existing RPC, schema, grants and numerical limit are unchanged.

IP identity is an internal server-to-server header for the existing rate-limit purpose. It is not added to pilot event JSON, public responses, source/SEO/CSV projections or application logs. Incoming caller-controlled proxy headers are not forwarded: the sender builds fresh metadata from its existing trusted ingress helper. Consent/version/session checks, the four public event phases, private-field rejection, same-origin rules, local/synthetic/nonproduction no-write modes and optional-measurement behavior remain in force. Native direct events still work without a proxy secret. Invalid/partial proxy proof fails closed before clients. Unknown ingress IP or missing configuration returns unavailable rather than claiming an accepted proxy event.

## Configuration proposal: BLOCKED, not executed

Both server deployments need the same dedicated `KINNSO_PILOT_PROXY_SECRET`: exactly 32 random bytes encoded as canonical base64url (43 characters). Never use a `NEXT_PUBLIC_` variable, Supabase key, receipt encryption key or provider credential. This source change does not create a key, read current secret values, set an environment variable, rebuild a Preview, deploy, run SQL or change the original Remix-Kinnso project. A1-A5 remain NOT_EXECUTED.

Before any future activation, an authorized owner must identify both deployment targets/environments and secret-store references, approve that exact setting and bounded role/traffic test, and verify clock alignment and the unchanged quota in those targets. The web target/owner and original blocked metadata are not invented. Under current A0, leave configuration and original hosted acceptance BLOCKED. Readiness is not promoted from schema:not_checked. No real guide author consent or image rights are supplied by this change.

Proposed operator checks after separate approval: two different visitor identities behind one proxy do not share quota; one visitor cannot gain another quota by direct access, changing session/requestId, a forged header, body/target tampering or stale proof; denied consent and local/synthetic modes make no client or sink calls. Retain exact target, candidate, counts and cleanup scope. No owned CI seed/reset may be applied to shared staging or production.

Rollback proposal, not an executed action: keep Git deployment holds; stop proxy ingestion under a separately approved configuration change, preserve the rate ledger/receipts and actual event IDs, and reconcile both endpoints before restoring traffic. Removing/mismatching the proxy key fails closed; direct native events are unaffected. Source revert must preserve deployment holds and does not imply permission to change keys, schema, fixtures, providers, schedules or production.
