# 創作者 C1–C5、旅人 T1–T5 與商戶 M1–M5 本機示例預覽

啟動：在倉庫根目錄執行 `node docs/prototypes/conversation-studio-local/server.mjs`，然後開啟 <http://127.0.0.1:3499/zh-HK/>。

這個獨立入口直接使用第一批實作的 React 元件。路由、創作者身分及 API 僅為本機示例替身，沒有執行 Next API、SQL、資料庫、模型、OAuth 或外部服務。既有 domain writer 與 capability 設定保留；新的任務介面只由本機預覽注入示例 adapter。

所有保存／發佈只在此程序的記憶體模擬，重啟程序即清空；「重設示例」可清除目前瀏覽器進度。只監聽 `127.0.0.1`，每個瀏覽器 cookie 分開保存示例狀態，頁面限制連線至本機來源。這不是真實 Auth、RLS 或資料庫隔離的驗收。

1. 共用首頁選「寫 guide」。
2. 用頂部按鈕填入 D1；勾選模擬原創聲明，按「加入文件」。也可加入 D2 私人示例。
3. 提問、按「討論已選文件」，展開「看看內容的依據」。這是來源摘錄模式，沒有 AI 或外部事實查證。
4. 按「另開 brief」，再按頂部「填入 brief 基本資料」。只選 D1 加入公開攻略預覽；D2 保持私人。
5. 「保存私人 brief」→「預覽交到 guide」→檢查完整內容、確認來源→「保存至既有 guide 草稿」。
6. 在既有 guide 編輯器修改內容；若有修改，先預覽及確認保存。按「發布結構化版本」，核對內容並勾選聲明，最後按「確認現在發布」。

最後的成功文案仍只代表本機示例回應，沒有內容公開上線。此預覽已加入原行程、guide、收藏及創作者相關工作區；其他功能仍保留在 app 程式中。這次補充不更改先前的 DB／hosted 驗收狀態。

## C2–C5

頂部任務列與任務範本可直接進入：

- C2：選「待補摘要」示例，開報告，進原編輯器補摘要，返回後重讀來源。
- C3：選紀錄類別及日期，保存含平台／分母缺口的私人報告；成果庫可重開。
- C4：選已接受的修訂合作，寫回應，核對里程碑、原提交及 1–5 條不重複 HTTPS 示例連結，再確認提交；結果是待審核。
- C5：選 v1 示例攻略，編輯新版名稱／摘要，保存提案、查看差異，確認交回原草稿，再在原編輯器另行確認發佈；版本頁可對照 v1 採用副本。

每份成果有自己的討論、證據及 revision。保存意圖先留在本機記憶體，瀏覽器僅保存恢復 UUID；未知結果會保留相同請求核對。來源停用後，報告及收據會拒絕讀取。

測試：`node docs/prototypes/conversation-studio-local/creator-flows.mjs`。也可用 `node docs/prototypes/conversation-studio-local/server.mjs 3500` 啟動隔離檢查入口，再將測試第一參數設為 `3500`。兩個入口都只監聽 loopback。

## T1–T5

從共用首頁的旅人入口或「任務範本」選擇任務；頂部的試走指引亦列出五個入口。旅人頁預設收起長指引與導覽，手機可直接開始；點擊即可展開所有原入口。

- T1：填自己的示例行程名稱、日期、時區及 1–5 個示例站點 → 讀取來源 → 另開私人 brief → 保存並讀回 → 確認建立 → 原行程編輯器。安排的時間是可修改示例，未核實交通或營業時間。
- T2：選收藏的結構化 guide 和自己的行程 → 看作者、版本及新增站點 → 私人 brief → 確認採用。既有私人筆記保留；只有摘要的 guide 會被拒絕。
- T3：選行程 → 逐項勾選站點及有權公開的示例圖 → 完整公開預覽 → 私人 brief → 確認分享 → 開啟唯讀連結 → 確認撤回。分享約六天後到期，只在同一電腦的本機服務可讀；撤回阻止新讀取，不刪除外部副本。
- T4：讀收藏 → 寫分類建議 → 可逐項選擇移除收藏 → 私人 brief → 確認。分類只留在私人 brief，沒有憑空新增正式分類功能。
- T5：選行程和站點 → 寫完整私人筆記／圖片描述 → 可選固定自有示例色塊 → 私人 brief → 確認。固定圖片先完成示例 finalize，再附加及讀回；真實檔案上載沒有開放。

「旅人 brief 庫」可以重開各個獨立任務。保存前先保留完整意圖，未知結果或重載沿用同一 UUID。所有任務都要另外讀回原資料，才顯示完成。記憶體資料隨程序重啟／重設清除；準備階段未完成前的文字不保證可復原。

旅人測試：`node docs/prototypes/conversation-studio-local/traveller-flows.mjs 3500`。

詳見 [旅人驗收報告](../../implementation/CONVERSATION_STUDIO_TRAVELLER_ACCEPTANCE.md)。

預覽專用的原編輯器暫存也放在本機服務記憶體，不寫 IndexedDB；重載可恢復未確認操作，重設／程序重啟會清除。啟動時會移除同一預覽來源的舊 `kinnso_account_cache_v1` 示例暫存。正式 app 的離線快取與原 writer 保持原樣。

## M1–M5

從首頁商戶入口或全部範本開始。共用提問框的問題會帶入商戶任務；先選公司，角色以目前示例成員資料為準。切換公司會清除未保存的草稿與確認，已保存成果可從「商戶 brief 庫」重開。

- M1：讀公司資料 → 修改公司簡介／聯絡資料等原欄位 → 查看前後差異 → 私人 brief → 保存並讀回 → 明確確認 → 原商戶表單。owner-only；地址／營業時間只可寫入私人備註。
- M2：選目前可用站內個案 → 讀原訊息證據 → 寫回覆 → 私人 brief → 核對指定個案及完整回覆 → 確認 → 原 receipt 和訊息讀回。沒有外部發信或貼文。
- M3：選自有公司／私人文件 → 三份可編輯素材 → 私人來源逐項用途確認 → 私人 brief → 公司活動草稿。未同意的私人資料只保存為私人 brief。WhatsApp Business／Instagram 未連接。
- M4：選活動 → 檢查缺項和完整條款 → 原編輯器補齊後儲存 → 新 M4 brief → 完整發佈確認 → 讀回已發佈示例。已發佈條款不可再當草稿覆寫。
- M5：選 UTC 建立日期範圍 → 看彙總、未知分母及未連接平台 → CSV → 私人報告 → 原成果頁。owner-only；核准不等於付款或營收。

連續試走 M3 → M4：建立活動草稿後按「接著做 M4 發佈前檢查」。先保存缺項報告並進原流程，按「修改已儲存草稿」，補優惠碼、HTTPS 網址、三項佣金比例及一個里程碑。儲存後返回 M4，選同一活動重讀來源，再核對並確認示例發佈。

商戶測試：`node docs/prototypes/conversation-studio-local/merchant-flows.mjs 3500`。測試使用隔離瀏覽器 session；不會清除使用者 3499 進度。商戶檔案、活動、支援與成果仍用原 clients／UI；本機替身重檢公司、來源與收據，不能替代正式 Auth／RLS／RPC 驗收。

詳見 [商戶驗收報告](../../implementation/CONVERSATION_STUDIO_MERCHANT_ACCEPTANCE.md) 及 [機器可讀證據](../../implementation/CONVERSATION_STUDIO_MERCHANT_EVIDENCE.json)。

## 旅程與優惠配對：階段 0–2 本機示例

沿用 `http://127.0.0.1:3499/zh-HK/`。原 C1–C5、T1–T5、M1–M5 和所有原導覽保留。

1. 首頁 →「商戶優惠展示」→ 選第一間 owner 商戶「海旁小店（示例）」→ 建立示例連結 → 兩端 owner 示例確認。這只是記憶體 fixture，並未連到 SMEAssistant。
2. 重讀示例優惠 → 匯入 → 核對城市、時區、每人計價、完整文字 → 準備展示預覽。逐項選所需的六種用途；完整試走需另選私人 brief、公開 guide、行程採用及行程分享。用途預設全不勾選。
3. 保存用途授權後，另行確認展示。示例內容權利只覆蓋這些自製資料，不能推論真實第三方內容已獲授權。
4.「旅程與優惠配對」→ 香港、2026-11-07 至 2026-11-09、每人 HKD 200、散步 → 保存私人意向 → 尋找合適優惠 → 收藏建議。配對原因與缺漏可展開；意向不會傳到商戶或 SMEAssistant。
5.「用這個配對寫 guide」→ 在 C1 按「讀取已收藏配對證據」→ 加入已授權來源 → 討論 → 另開 brief → 填自己的名稱、城市和摘要 → 保存私人 brief → 完整預覽 → 原 guide 編輯器 → 完整發佈確認。
6. 到 T2 選這個剛發佈的示例 guide，核對作者／版本並採用；再到 T3 逐項選站點、預覽、分享及撤回。自己的筆記保持私人。授權不足會拒絕，撤回後舊連結不能再讀受限來源。
7. 商戶可撤回單項用途或整個展示；「已連接帳號」也可撤銷示例連結。來源到期或版本改變需要重新核對；修改確認內容後要重新預覽。

收藏城市不等於已安排旅程。未決日期、未知價格或幣別顯示待確認，不當作零。佣金不參與排序；合作入口仍使用原活動流程，配對不代表合作申請獲批。T1 只預填自己的城市／日期，商戶文字留在參考卡，取得行程採用授權後才由原 T2 流程加入。

新端到端測試：`node docs/prototypes/conversation-studio-local/discovery-flows.mjs 3501`，拒絕在使用者 3499 session 跑重設測試。所有寫入先留意圖，再讀回核對；逾時保留原 UUID，顯示結果未知。程序重啟會清空全部示例記憶體。

來源封包：先在 `apps/journeys` 執行 `python scripts/package-source.py`，再於倉庫根目錄執行 `python docs/prototypes/conversation-studio-local/package-local-source.py`。原 app 封包保留 GPL-3.0；補充封包 `apps/journeys/public/source/kinnsoos-local-discovery-source.zip` 保留 app、示例 server、測試與工具契約的原相對位置及逐檔雜湊。兩者不包含私密設定、依賴或測試紀錄；補充封包不改原 app packer 的父目錄檔案限制。

完整驗收與限制見 [階段 0–2 本機驗收](../../implementation/TRIP_OFFER_MATCHING_PHASE_0_2_ACCEPTANCE.md)。正式資料庫／Auth／RLS、真實 MCP、社群發文、訂位、付款與收入仍未開放。
